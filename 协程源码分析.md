# Kotlin协程源码分析

## 概述

本文档通过分析协程的源码实现，详细解释协程是如何在线程基础上运行的。

## 核心概念

### 1. 协程的本质

协程本质上是一个**可挂起、可恢复的函数**，它通过**状态机**和**Continuation**机制实现。

### 2. 关键组件

- **CoroutineScope**: 协程作用域
- **CoroutineDispatcher**: 协程调度器（决定在哪个线程执行）
- **Continuation**: 续体（保存协程的执行状态）
- **SuspendFunction**: 挂起函数

## 源码分析

### 1. CoroutineScope.launch 的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/Builders.kt
public fun CoroutineScope.launch(
    context: CoroutineContext = EmptyCoroutineContext,
    start: CoroutineStart = CoroutineStart.DEFAULT,
    block: suspend CoroutineScope.() -> Unit
): Job {
    val newContext = newCoroutineContext(context)
    val coroutine = if (start.isLazy)
        LazyStandaloneCoroutine(newContext, block) else
        StandaloneCoroutine(newContext, active = true)
    coroutine.start(start, coroutine, block)
    return coroutine
}
```

**关键点：**
- 创建新的协程上下文
- 创建协程实例（StandaloneCoroutine）
- 启动协程

### 2. StandaloneCoroutine 的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/AbstractCoroutine.kt
public abstract class AbstractCoroutine<in T>(
    parentContext: CoroutineContext,
    initParentJob: Boolean,
    active: Boolean = true
) : JobSupport(active), Job, Continuation<T>, CoroutineScope {
    
    public final override fun resumeWith(result: Result<T>) {
        val state = makeCompletingOnce(result.toState())
        if (state === COMPLETING_WAITING_CHILDREN) return
        afterResume(state)
    }
}
```

**关键点：**
- AbstractCoroutine 实现了 Continuation 接口
- resumeWith 方法用于恢复协程执行

### 3. 调度器（Dispatcher）的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/scheduling/CoroutineScheduler.kt
internal class CoroutineScheduler(
    private val corePoolSize: Int,
    private val maxPoolSize: Int,
    private val idleWorkerKeepAliveNs: Long = IDLE_WORKER_KEEP_ALIVE_NS,
    private val schedulerName: String = DEFAULT_SCHEDULER_NAME
) : Executor, Closeable {
    
    override fun execute(command: Runnable) {
        val task = TaskImpl(command, submissionTime = schedulerTimeSource.nanoTime())
        if (addToGlobalQueue(task)) {
            requestCpuWorker()
        } else {
            // 队列满了，拒绝任务
            throw RejectedExecutionException("$schedulerName was terminated")
        }
    }
}
```

**关键点：**
- CoroutineScheduler 是一个线程池
- 通过 execute 方法将任务提交到线程池
- 线程池中的线程执行协程任务

### 5. delay 函数的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/Delay.kt
public suspend fun delay(timeMillis: Long) {
    if (timeMillis <= 0) return
    return suspendCancellableCoroutine sc@ { cont: CancellableContinuation<Unit> ->
        cont.context.delay.scheduleResumeAfterDelay(timeMillis, cont)
    }
}
```

**关键点：**
- 使用 suspendCancellableCoroutine 挂起协程
- 通过调度器安排延迟恢复

### 6. withContext 的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/Builders.kt
public suspend fun <T> withContext(
    context: CoroutineContext,
    block: suspend CoroutineScope.() -> T
): T {
    return suspendCoroutineUninterceptedOrReturn sc@ { uCont ->
        val oldContext = uCont.context
        val newContext = oldContext + context
        if (newContext === oldContext) {
            return@sc block.startCoroutineUninterceptedOrReturn(uCont)
        }
        
        val interceptor = newContext[ContinuationInterceptor]
        if (interceptor == null) {
            return@sc block.startCoroutineUninterceptedOrReturn(uCont)
        }
        
        val intercepted = interceptor.interceptContinuation(uCont)
        block.startCoroutineUninterceptedOrReturn(intercepted)
    }
}
```

**关键点：**
- 检查是否需要切换调度器
- 如果需要切换，使用 ContinuationInterceptor 拦截续体
- 在新的上下文中执行代码块

### 7. ContinuationInterceptor 的实现

```kotlin
// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/CoroutineDispatcher.kt
public abstract class CoroutineDispatcher : AbstractCoroutineContextElement(ContinuationInterceptor), ContinuationInterceptor {
    
    public final override fun <T> interceptContinuation(continuation: Continuation<T>): Continuation<T> {
        return DispatchedContinuation(this, continuation)
    }
}

// kotlinx-coroutines-core/src/main/kotlin/kotlinx/coroutines/internal/DispatchedContinuation.kt
internal class DispatchedContinuation<T>(
    val dispatcher: CoroutineDispatcher,
    val continuation: Continuation<T>
) : DispatchedTask<T>(MODE_UNINITIALIZED), Continuation<T> by continuation {
    
    override fun resumeWith(result: Result<T>) {
        val context = continuation.context
        val state = result.toState()
        if (dispatcher.isDispatchNeeded(context)) {
            _state = state
            resumeMode = MODE_ATOMIC
            dispatcher.dispatch(context, this)
        } else {
            executeUnconfined(state, MODE_ATOMIC) {
                withCoroutineContext(this.context, countOrElement) {
                    continuation.resumeWith(result)
                }
            }
        }
    }
}
```

**关键点：**
- CoroutineDispatcher 实现了 ContinuationInterceptor
- interceptContinuation 返回 DispatchedContinuation
- DispatchedContinuation 负责在正确的线程上恢复协程

## 线程切换的具体过程

### 1. 协程启动时的线程切换

```kotlin
// 当调用 CoroutineScope(Dispatchers.IO).launch 时：
// 1. 创建 CoroutineScope，指定 Dispatchers.IO
// 2. 调用 launch 函数
// 3. 创建 StandaloneCoroutine
// 4. 调用 coroutine.start()
// 5. 最终调用 DispatchedContinuation.resumeWith()
// 6. 检查是否需要切换线程
// 7. 如果需要，调用 dispatcher.dispatch(context, this)
// 8. 将任务提交到IO线程池
// 9. IO线程池中的某个线程执行协程体
```

### 2. delay 时的线程切换

```kotlin
// 当调用 delay(10) 时：
// 1. 调用 suspendCancellableCoroutine
// 2. 协程被挂起，保存当前状态
// 3. IO线程被释放，可以执行其他任务
// 4. 调度器安排10ms后恢复协程
// 5. 10ms后，协程恢复执行
// 6. 可能在同一个IO线程上恢复，也可能在不同的IO线程上恢复
```

### 3. withContext 时的线程切换

```kotlin
// 当调用 withContext(Dispatchers.Main) 时：
// 1. 检查是否需要切换调度器
// 2. 如果需要，创建新的 ContinuationInterceptor
// 3. 协程在IO线程上被挂起
// 4. 任务被提交到主线程
// 5. 主线程执行 withContext 内部的代码
// 6. 执行完成后，结果被传回IO线程
// 7. 协程在IO线程上恢复执行
```

## 状态机的实现

编译器将协程转换为状态机：

```kotlin
// 编译器生成的伪代码
class ContinuationImpl : Continuation<Unit> {
    private var state = 0
    private var count: Int = 0
    private var num: Int = 0
    
    override fun resumeWith(result: Result<Unit>) {
        when (state) {
            0 -> {
                // 状态0：初始化
                count = 19 * Random.nextInt(17)
                state = 1
                delay(10, this) // 挂起
            }
            1 -> {
                // 状态1：delay后
                println("ceshi***1-${count}")
                state = 2
                withContext(Dispatchers.Main, this) { // 挂起
                    println("ceshi***2-${count}")
                    5
                }
            }
            2 -> {
                // 状态2：withContext后
                num = result.getOrThrow()
                println("ceshi***3-${num}")
                // 协程完成
            }
        }
    }
}
```

## 关键理解点

1. **协程不是线程**：协程是在线程上运行的轻量级任务
2. **调度器决定线程**：CoroutineDispatcher 决定协程在哪个线程执行
3. **挂起不阻塞线程**：协程挂起时，线程被释放去执行其他任务
4. **状态机保存状态**：编译器生成的状态机保存协程的执行状态
5. **Continuation 实现恢复**：通过 Continuation.resumeWith() 恢复协程执行

## 总结

协程通过以下机制在线程基础上运行：

1. **调度器**：决定协程在哪个线程执行
2. **状态机**：保存协程的执行状态
3. **Continuation**：实现协程的挂起和恢复
4. **线程池**：提供执行协程的线程资源

这种设计让协程能够高效地利用线程资源，实现非阻塞的异步编程。
